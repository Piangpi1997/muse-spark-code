## Wire and design evidence

Muse Code 1.3.0 MSP schema lists `session/fork` with optional
`cutPoint.lastTurnId`. Its TUI docs describe `/rewind` and `/side` (`/btw`),
but the MSP inventory lists no `session/rewind` or `session/sideChat` method.
The implementation reuses the existing fork parser and history item schema;
it introduces no guessed MSP item or response shape. The known Windows
`session/fork` refusal still gates the controls off there. The Model API
backend's image bytes come from its stored input replay, not from the CLI's
attachment metadata.

The original Claude M53 worktree supplied the image-replay accessor and
completed-turn fork work. Its checkpoint started from M45 `cdf7f2c`;
this isolated integration includes `cdf7f2c..ef84852` and now sits on
M45's main merge `19086734`. The merge commit and `ef84852` have identical
tree `312268ad8f0b94656c96ee1ababfdf3a69045a4a`; a soft base move
preserved every staged M53 path. Source worktree remains untouched.

## Focused stale side-chat boundary audit

The M53 checkpoint bound rewind messages to their source session, but the
side-chat message carried no session ID. A delayed click from the previous
session could therefore fork the new one shown in the same tab. The local
fake test switched from `s1` to `old`, delivered the old side-chat click,
and observed an unexpected `session/fork` (exit 1). Protocol tests also
showed that the boundary accepted a missing or empty source ID and stripped
one supplied by the panel (3 failures, exit 1).

The button now sends the session ID at click time, the postMessage schema
requires it, and the controller compares it with the current session before
host lookup. The same three affected files passed 284/284 focused tests;
host, webview and unit TypeScript checks passed. These are local fake checks
only. The earlier M53 integration backup `a497bd52d8052609e04cfb31cd6c4c52757dd997`
was preserved; full quality, browser accessibility and earlier milestone
