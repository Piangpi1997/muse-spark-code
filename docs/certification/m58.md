# M58: a popup before every paid use

Recorded 2026-09-27 on branch `feature/m58-paid-consent`, from main `2f4f669`
(0.9.0). PLAN.md D48.

## The request

The owner (2026-09-27): "anything requiring extra payment should promt you
with a popup that asks allow once allow always in this workspace or deny".

Before M58 the paid features asked in four ways. A Model API image or child
task asked on an in-chat card with **Allow once** and **Reject**. An image on
Muse Code, a scheduled run and a child task started from the Agent map asked
in a native dialog with one accept button. Web search and Muse Voice asked
nothing per use: their price was accepted once, when they were turned on.

## What was built

- **`PaidUseConsent`** (`src/core/paid/paidConsent.ts`, no `vscode`): a use
  is allowed when its feature is on and either allowed always in this
  workspace or allowed in the popup now. `requiresAsking` asks even when it
  is allowed always. A feature turned off while the popup was open is
  refused whatever the answer. **Ask again** clears the workspace's grants.
- **`askPaidUse`** (`src/host/paid/paidHost.ts`): the native modal. It names
  the use and its price and offers **Allow once**, **Allow always in this
  workspace** and **Deny**; Deny is the close affordance, so closing it
  denies. "Always" is offered only when `canRememberPaidUse` holds: a trusted
  workspace with a folder open. A child task on a model without verified
  rates is refused before any popup, as before.
- **Grants.** They are kept in `workspaceState`
  (`museSpark.paidWorkspaceGrants`: feature → generation). A change to a
  feature's price acceptance (turned off, or a new price accepted) counts its
  generation up in `globalState` (`museSpark.paidGrantGenerations`), so every
  workspace's "always" for it lapses. A malformed or older grant is ignored.
- **The Model API host.** Images and child tasks ask through the popup
  instead of a card. The `PermissionRequest` hook still runs first: its deny
  refuses, and its allow never answers the popup. A PreToolUse hook that
  forces approval, and an image aimed at a protected path, ask even when the
  feature is allowed always. Web search asks once per prompt, before its
  first request. Deny sends the prompt without `web_search` and without
  `web_search_call.results`. A child task carries its parent prompt's
  answer in its grant, or for a task started from the Agent map with no
  prompt running, whether web search is allowed always. A child never asks
  for itself. `paidChoices`, the `paidTool` subject and its `paidFeature`,
  `modelId` and `requestLimit` fields are removed.
- **Muse Voice.** The controller asks before each recording on the paid
  engine, only when it can record. A stop pressed while the popup is open
  cancels the start.
- **Scheduled runs and Muse Code images** use the same popup through the
  existing `confirmScheduledRun` and `ideImageTools` `confirm` hooks.
- **The panel.** Account & usage marks a feature "on, allowed always in this
  workspace". It names such features and offers **Ask again every time**
  (the `forgetPaidUse` message). The paid badge's tooltip names them too.
  The approval card lost its paid branch and CSS.
- **Strings.** They are in `en.ts` and the 14 UI tables. The five paid
  settings' descriptions are updated in all 15 manifest tables.
  `check:l10n` reports 0 problems.
