# M60: the shell sandbox stays off on Termux/proot Linux

Recorded 2026-09-28. PLAN.md D12, complements M59 (verified tree kills on the
same hosts).

## The problem

On code-server inside proot Ubuntu on Termux, `resolveShellSandbox` knew only
the Windows profile-workspace exception, so `auto` kept Muse Code's OS
sandbox on Linux. proot (and Termux itself) has no namespaces for that
sandbox, and every shell-tool call failed with `sandbox enforcement
unavailable`. Unlike Windows, Linux had no recovery path: the setup offer in
`sandboxSetup.ts` early-returns off Windows, so the failure repeated every
turn.

## What was built

- **`isProotEnvironment`** (`src/core/backends/musecode/sandbox.ts`, pure,
  environment injected): true when `PREFIX` points under Android app storage
  (`/data/data/`, `/data/user/`), or `TERMUX_VERSION`, `ANDROID_ROOT` or
  `ANDROID_DATA` is set. proot inherits Termux's environment, so the markers
  survive into the Ubuntu guest; a Termux-native host (code-server started in
  Termux itself) is equally constrained and counts too. A desktop `PREFIX`
  such as `/usr/local` does not fire.
- **`resolveShellSandbox`**: under `auto`, on `linux` with `isProot`, returns
  `{ isSandboxed: false, reason: 'proot' }`, so `serveArguments` passes
  `--disable-sandbox` and approval cards keep gating every command (the
  Claude Code model, per D12). An explicit `muse`/`off` still wins; the
  signal is ignored off Linux. No new UI text: the spawn log (`Shell sandbox
off (proot) for this host`) and the Diagnostics posture line carry the
  reason, and `extension.ts` already skips the sandbox offer when the window
  will not sandbox.
- **Wiring** (`MuseCodeBackendManager.shellSandboxPosture`): passes
  `isProotEnvironment(process.env)`. The launch cache key already includes
  the serve arguments, so a posture change respawns the host.
- **Docs**: README `shellSandbox` row and the no-sandbox caveat name
  Termux/proot; the English `config.shellSandbox.enumDescriptions.auto`
  says the same. The 14 manifest translations keep the older sentence until
  the next translation pass.

## Tests

- `test/unit/sandbox.test.ts`: `isProotEnvironment` on Termux/proot/desktop
  environments (5 true, 4 false cases); `resolveShellSandbox` off with
  reason `proot` under `auto` on proot Linux; explicit `muse`/`off` winning;
  proot ignored on darwin.
- `test/unit/museCodeBackendManager.test.ts`: posture is `default` on a
  desktop env and `proot` with a Termux `PREFIX` under `auto`; explicit
  settings win.
