## Source contract

- [Muse Code SDK 1.3.0 settings-level hooks](https://meta-models.github.io/muse-code-sdk/next/guides/extend/hooks/): managed, user, project order; project trust; JSON config; matcher and handler rules; shell execution and cleared environment. Its examples include observed stdin frames.
- [Muse Code SDK 1.3.0 hook events and payloads](https://meta-models.github.io/muse-code-sdk/next/guides/plugins/reference/hook-events/): 17 events, common and event-specific stdin, closed output schema, exit codes, 256 KiB stdin and independent 16 KiB output caps.

## Implemented in the isolated M51 worktree

- Machine-scoped `museSpark.modelApiHooks`, off by default. A new Model API session loads managed, user and trusted-project sources in that order.
- Config validation warns and skips unsupported or malformed entries. Fifteen events in `PLAN.md` M51 have dispatch points; `SessionEnd` runs on orderly host shutdown within a 10 second total budget, and `Notification` starts after an approval has waited six seconds. Bounded regex matchers, asynchronous observation handlers and three levels of `onFailure` are implemented. Hook answers can deny prompts/tools, request ordinary approval, rewrite tool inputs before normal validation and approval, add model context or keep a stopped turn working within a continuation cap. A `PermissionRequest` hook may allow an ordinary approval; paid calls, protected writes and a `PreToolUse` forced approval still require the user's card. This follows the SDK's documented `decision.behavior` semantics with the project's stricter D24/D30 guards.
- `PreLLMCall` runs before each logical Model API response stream and compaction request. Its captured `decision: "block"` refuses before HTTPS. `PostLLMCall` runs after a completed response with the captured success fields. The local `provider` is `meta`, not a claim about Muse Code's provider id. Hook stdin contains bounded text summaries: last 32 messages, four text parts per message, 256 characters per part, 50 tools with 256-character descriptions, and 1,024 characters of output preview. Inline media bytes, full tool outputs and the API key are excluded. A foreground post-call block stops with a failed turn before returned tools or another request; returned function calls receive failure outputs for valid replay. Its continuation behavior in Muse Code remains uncaptured. Compaction keeps prior history on a post-call block while counting the completed response's usage. A whole-stream retry has a fresh PreLLMCall and a PostLLMCall only after success; automatic HTTP retries inside one stream share the logical hook boundary.
- Commands use JSON stdin and a narrow environment without provider keys. Relative PATH entries are removed. Managed hooks receive only valid `managed_hooks_env_vars` grants; duplicate and provider credential names are rejected. Timeout, 16 KiB per-stream output cap, process-tree cancellation and Stop cancellation use the host's existing process runner. A global four-command cap prevents many sessions from spawning unbounded hook processes.
- `test/unit/modelApiHooks.test.ts`, `modelApiHost.test.ts`, `modelApiBackendManager.test.ts`, `toolIo.test.ts` and `settings.test.ts` cover the bounded runtime. The manager case independently asserts the machine opt-in prevents a `SessionStart` command from running. A real `runHook` process test sends JSON over stdin and reads its answer; it uses no Model API key or model call.
