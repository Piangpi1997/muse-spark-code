## Source and boundary

- Meta's [interactive guide](https://dev.meta.ai/docs/muse-code/interactive)
  documents `/loop` interval and five-field local cron syntax, a default
  ten-minute cadence, skipped occurrences during active runs, and the
  seven-day lifetime.
- Meta's [loop and cron recipe](https://dev.meta.ai/docs/cookbook/loop-and-cron)
  says jobs belong to a session, need a running process, recover at most one
  missed recurring occurrence, and are cancelled by ID through the agent's
  tools. M43's [live capture](m43.md) recorded the exact `cron_create`,
  `cron_list`, and `cron_delete` tool row shapes. Muse Code 1.3.0 has no MSP
  scheduler verbs or `muse cron` CLI command. M52 therefore does not pretend
  the panel can directly list or cancel its native jobs.
- Meta's [pricing table](https://dev.meta.ai/docs/pricing-rate-limits),
  checked again 2026-09-26, lists standard rates of $1.25 per million input,
  $0.15 per million cached input and $4.25 per million output tokens; the
  contributor rates are $0.10, $0.002 and $0.20 respectively. Feature enable
  names both tiers; each per-run dialog names only its selected model's tier
  and says total spend depends on usage.

## Model API design

- `/loop` parses an exact interval or five-field local cron expression;
  `/loop list` and `/loop cancel <id>` make no Model API call. Job files live
  under VS Code's per-workspace storage directory, with session ID and a
  SHA-256 digest of the current SecretStorage key as boundaries. The raw key
  is never persisted or sent to the webview. Every job expires after seven
  days; an interval first due at expiry is refused before storage. Only
  loaded sessions poll for due jobs; polling never sends a model
  request.
- A due job stays pending until Run, Cancel or expiry. The scheduled-prompts setting is machine-scoped,
  off by default, and becomes usable only after the paid-feature gate's
  price confirmation. Run asks again with the prompt, model and published
  token rates, including in Bypass. Decline makes no request. The core
  rechecks gate, key and due state immediately before admission.
- Admission creates a per-occurrence receipt with exclusive file creation.
  Two windows cannot admit the same occurrence. Receipt remains after a
  crash or failed turn; one possibly billed request is never silently
  replayed. A recurring schedule advances from admission time without a
  backlog. A running turn blocks admission. Run appears as its own paid
  transcript row, and its count appears in Account & usage. Its token cost
  remains in the session's existing token estimate to avoid double counting.

## Cron wildcard correction, 2026-09-26

but does not specify its day-of-month/day-of-week combination for star steps.
The [crontab(5) manual](https://man7.org/linux/man-pages/man5/crontab.5.html)
says those fields use OR only when neither contains `*`. This is the standard
cron interpretation applied to M52's extension-owned scheduler; it is an
inference, not a captured claim about Muse Code's native scheduler.

restricted field and scheduled a Tuesday run through OR. A second assertion
ensures `*/2` retains its day values under AND, and a test confirms explicit
`1-31` has no star and remains syntactically restricted for OR. `cronField`
now records any field containing `*` as star syntax; the matcher ANDs the
actual day and weekday values when either has it, otherwise ORs them. The
focused suite went from one failure and one pass to **8/8 passing**. No model
attempt or paid call was made.
