# M57 — The Model API backend out of the activation bundle (PLAN.md D6, M57)

Recorded 2026-09-27 on `feature/m57-bundle-split`, from main `2f4f669`
(0.9.0). No live model call, no credential, no push.

## Why

At 0.9.0 `dist/extension.js` was 596.8 KiB of its 600 KiB budget, and 180.7
KiB of it was `src/core/backends/modelapi/**`, which only a conversation on
the Model API backend uses. The budget stays; the backend moves into
`dist/modelApi.js`, which `ModelApiBackendManager.build()` requires the first
time that backend starts.

## The gate

`scripts/check-bundle-split.mjs`, in `npm run build` after the size check,
reads `dist/meta/extension.json` and `dist/meta/modelApi.json` and fails when
a file of the explicit 20-file lazy list (the host, `tools`, `hooks`,
`goals`, `instructions`, `mediaBudget`, `memoryTools`, `modelCallHooks`,
`permissions`, `promptCache`, `subagentTools`, `toolHookPayload`, `glob`, and
the seven `mcp/` files) or the entry is in the activation bundle, when the
Model API bundle stops carrying one of them, or when a file of the folder is
on neither list (or both). Beside it: `dist/modelApi.js` in
`check-bundle-size.mjs` (400 KiB, and a missing bundle now reported as
`MISS` rather than a stack trace) and in `check-host-globals.mjs`; the
notices script reads every metafile, so it covers the new bundle, and its
header names it (`THIRD_PARTY_NOTICES.txt` regenerated, 75 packages, header
only); `knip.jsonc` and `npm run cycles` take the entry (without it dpdm
analysed 203 files and never reached the backend; with it, 227);
`.vscodeignore` ships the file (`npx vsce ls --no-dependencies` lists
`dist/modelApi.js`); CI's package job requires it in the `.vsix`.
